# 平台适配契约

> 这份文档写给两种人：**要给控制面换一个聊天平台的人**，和**被派去实现它的 Agent**。
>
> 它不教你怎么调用某个平台的接口 —— 那些看官方文档。它只回答一件事：
> **从一个平台换到另一个平台，到底要重答哪些问题。**

---

## 一、先立一个前提：平台能力不齐是常态

聊天平台不是同一套东西的四种界面。它们长得像，能力差得很远：

有的能改已经发出去的那条消息，有的不能；有的卡片能带可点击按钮并回调，有的只有模板；有的保证"只有 @ 机器人的消息才推给你"，有的把整群消息都推过来让你自己筛。

**所以不要写"通用适配层"，要写"能力档位 + 显式降级"。**

> 缺能力的时候，正确做法是**声明它缺**，并且降级到一个说清楚的形态；
> 错误做法是用别的东西凑 —— 凑出来的东西看起来能用，但语义已经变了。

这条和我们处理运行器（harness）时的原则是同一条：**约定通用，实现专属。**

## 二、四条能力轴（决定一个平台能到什么档）

| 轴 | 它撑起的是哪条设计 | 缺了会怎样 |
|---|---|---|
| **① 长连接**（应用主动外连，不需要公网 IP） | 个人电脑/家用网络能不能常驻 | 只剩 webhook ⇒ **需要公网地址**，等于放弃"电脑上能跑，手机上就能用"这个前提 |
| **② 可更新已发消息** | 流式气泡、真进度 | 退回"一段一条"的分段推送，进度变成低频状态消息 |
| **③ 可交互卡片 + 回调** | 审批拦截（否决权在人这一侧） | 该平台**不能提供「逐次询问」档** |
| **④ 协议级 @ 隔离**（平台只推 @ 机器人的消息） | 人是唯一路由器 | 降级成应用层过滤，**安全等级下调一档**，必须写明 |

⑤ 消息大小上限与推送频率不是"有没有"的问题，是"多大"的问题 —— 每个平台都要各自量，没有默认值可抄。

---

## 三、8 个平台适配点

换平台时，逐条回答这 8 个问题。它们的地位和教程 [§8 的「6 个运行器适配点」](../docs/claude-code-wecom-guide.md) 一样：
**问题是一样的，答案是每个平台自己的。**

| # | 适配点 | 要回答什么 | 企业微信的答案（已实测，作为基准） |
|---|---|---|---|
| 1 | **建连与重连** | 谁主动连谁？心跳多久？断了怎么退避？ | 桥主动外连 `wss://openws.work.weixin.qq.com`；30s 心跳；指数退避 3s→30s，连上即重置 |
| 2 | **收消息 + 结构化 @ + 去重** | 怎么只收 @ 自己的？重复投递怎么认？ | 长连接回调；平台只推 @ 机器人的消息；按消息 id 去重 |
| 3 | **发消息 + 更新同一条** | 已经发出去的那条，能不能改？ | 能：回执与正文**共用同一个 `stream.id`**，气泡原地刷新 |
| 4 | **发卡片 + 规格限制** | 卡片有哪些写死的限制？ | 模板卡片；⚠️ 按钮文字**只有 2 个字的余量**，4 个字会被截成「清...」 |
| 5 | **收卡片回调** | 用户点了按钮，事件怎么回来？ | 卡片事件回调带 `callback_id`，回执走另一条通道 |
| 6 | **分片与错误码** | 超过上限怎么办？失败怎么知道？ | 单条上限 20480 字节；**被 `40058` 拒了才切片**，每片等回执 |
| 7 | **身份与白名单** | 谁是"允许指挥这台机器的人"？ | `from.userid` 白名单，**留空即拒绝启动**（fail-closed） |
| 8 | **限流与节流** | 多久能推一次？ | "变化才推" + 60s 兜底心跳 |

### 每一条的通过判据

| # | 判据（能做到才算答对了） |
|---|---|
| 1 | 断网 30 分钟后能自己回来；**不会因为重连而重复执行**任何任务 |
| 2 | 同一条消息投递两次，只执行一次；收到的每条消息都能追溯到一个确定的身份 |
| 3 | 能看到"正在跑 + 第几步 + 当前工具"在同一条消息里变化，而不是刷屏 |
| 4 | 按钮文字**实测**没被截断；点下去能拿到唯一确定的回调 |
| 5 | 回调重复到达时不会重复放行危险动作 |
| 6 | 超长回答的每一片都能确认送达；哪一片没送到能明说 |
| 7 | **白名单留空时拒绝启动**，而不是"先跑起来再说" |
| 8 | 突发流量下不触发平台限流，且限流时不丢消息 |

## 四、降级规则

缺一条能力，就按这张表降，**并且必须在 `/status` 里如实显示**：

| 缺哪条 | 降级成什么 | 明确不能做的事 |
|---|---|---|
| **② 可更新消息** | 分段发送：一段一条消息；进度改为低频状态消息 | 不能对外声称"流式气泡" |
| **③ 交互卡片 + 回调** | **该平台不提供「逐次询问」档**，只有只读 / 全自动两档 | 不能拿"回复「允许」"这类文本指令凑合 —— 消息可以被伪造、可以被别的消息打断，否决权就不再是确定的 |
| **④ 协议级 @ 隔离** | 应用层自己判断是否 @ 了机器人 | 不能把它描述成"协议层隔离"；安全说明里要写明这一档更弱 |
| **① 长连接** | 只剩 webhook（需要公网可达地址） | 不能继续承诺"个人电脑上常驻、不要公网 IP" |

## 五、换平台后的验收清单

八条都过，才算这个平台接对了：

- [ ] 白名单留空 ⇒ **拒绝启动**
- [ ] 同一条消息重复投递 ⇒ 只执行一次
- [ ] 危险动作能被拦下，**否决权在拦截方**（超时/崩溃默认拒绝，不是默认放行）
- [ ] `/stop` 杀的是**整个进程树**，不是外壳
- [ ] 超长回答分片，且每片有回执；丢了哪片能明说
- [ ] 断线能自愈，重连后不重复执行
- [ ] `/new` 之后，模型**拿不到上一轮内容**（包括本机会话存储、桥自己的日志）
- [ ] 平台不支持的能力，在 `/status` 里如实显示为"不支持"，不是静默降级

> 最后一条最容易被跳过：**一个平台缺什么，用户有权在界面上看见。**
> 静默降级比不支持更糟 —— 用户会以为自己在用完整的权限保护。

---

## 六、这份契约的边界

它管的是"**平台层**"。下面这两层换平台时不动：

- **核心层**：队列、会话映射、命令、代次（epoch）、忙碌语义、审批状态机
- **运行器层**：那 6 个适配点

换句话说，换平台是一个**有边界**的工作：脏，但不难；而且做完之后，上面两层一行都不用改 ——
这正是"内核 + 适配器"这个结构的价值所在。
