# 企业微信 —— 参考实现

**状态：真机验收完成，且被两个互不知情的 Agent 独立复现过。**

这一页是四个平台里的基准：后面每个平台页的 8 个适配点，都是拿它当对照写的。
完整的接入步骤、实测数据、必须自己实现的 10 个机制，都在
[接入教程](../../docs/claude-code-wecom-guide.md) 里 —— 这里只留平台层的那份答案。

---

## 为什么是它

- **入口天然是聊天。** 企微在一个人的一天里，本来就是待得最久的地方之一。
- **不需要公网 IP。** 桥主动外连，家里一台常开的电脑就够 —— 这是整套方案的前提。
- **"企业微信"这四个字，和「一人公司」这个定位是同一个语汇。**

---

## 8 个适配点，它的答案

| # | 适配点 | 答案 |
|---|---|---|
| 1 | 建连与重连 | 主动外连 `wss://openws.work.weixin.qq.com`；30s 心跳；指数退避 3s→30s，连上即重置 |
| 2 | 收消息 + @ + 去重 | 长连接回调；平台只推 @ 机器人的消息；按消息 id 去重 |
| 3 | 发消息 + 更新同一条 | 回执与正文共用同一个 `stream.id`，气泡原地刷新 |
| 4 | 发卡片 + 规格限制 | 模板卡片；⚠️ 按钮文字只有 2 个字的余量，4 个字会被截成「清...」 |
| 5 | 收卡片回调 | 卡片事件回调带 `callback_id`；回执走另一条通道 |
| 6 | 分片与错误码 | 单条上限 20480 字节；被 `40058` 拒了才切片，每片等回执 |
| 7 | 身份与白名单 | `from.userid` 白名单，**留空即拒绝启动**（fail-closed） |
| 8 | 限流与节流 | "变化才推" + 60s 兜底心跳 |

四条能力轴：① 长连接 ✅ ② 可更新消息 ✅ ③ 交互卡片 ✅ ④ @ 隔离 ✅ —— 全满，所以这个平台能提供完整的
「逐次询问」档。

---

## 它踩过的坑（换平台时会再遇到）

这几条不是企微独有的，是**所有聊天平台都会遇到的形状**，只是答案不同：

- **按钮文字有长度限制**，而且是写死的、不报错的截断。换平台第一件事就该去量它。
- **`dontAsk` 档下，审批 hook 不能越过权限档位** —— 勾了「允许」也不执行。
  这条决定了审批卡片的定位：它是"已经决定全自动"之后加的第二道闸，不是"让全自动变安全"的东西。
- **`/new` 清的是模型上下文，不是可获取的信息源。** 换平台之后这条依然成立，而且**每个平台都要重新验一遍**。
