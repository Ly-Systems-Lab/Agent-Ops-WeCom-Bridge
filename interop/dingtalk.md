# 钉钉 · 执行面（`dws`）

**状态：✅ 已接入并实测（2026-11-10）—— 读与写都经本项目审批闸门跑通。**

> 本项目**不写钉钉聊天通道** —— 官方 `dws dev connect` 已覆盖"群 @ → 本机 AI"。
> 那个取舍写在 [`platforms/dingtalk/`](../platforms/dingtalk/README.md)；
> 这一页只讲 **Agent 怎么用 `dws` 干活**。

---

## 1. 官方给了什么

| 层 | 能力 |
|---|---|
| **CLI** | 钉钉工作台命令行：文档、表格、待办、审批、日历、会议、邮箱、通讯录等工作区服务 |
| **事件** | `dws event consume`，公开事件流（NDJSON），可喂给常驻 Agent |
| **数字员工** | `dws dingtalk-tag`，可把 `local_agent` 类型绑定到本机 Agent |
| **通道（我们不用）** | `dws dev connect`：群 @ 机器人 → 本机 AI，多轮、`/new` `/clear`、白名单、限流 |

三者的区别值得说清：**CLI 是"手"，事件流是"耳朵"，`dev connect` 是"嘴巴"**。
本项目只缺"嘴巴"吗？不缺 —— 我们已经有入口了；缺的是**手**，所以只接前两个。

## 2. Agent 怎么用

✅ 已验证（2026-11-10）：

```bash
dws <path> --help                      # 命令是否存在、当前二进制接受哪些 flag
dws schema "<path>" --compact          # Agent 该读的契约视图（正向字段白名单）
dws <path> --dry-run                   # 预览，不执行
dws <path> --jq '<表达式>'              # 精确取值，省 token
```

实测跑过的命令：`contact user get-self`、`todo +get-my-tasks`、`todo +get`、`todo +create`。

🔴 **`--yes` 是这一页的重点。**
官方要求 Agent 调用时**必须**带 `--yes`，它会**跳过 CLI 自身的交互确认**
⇒ 对本项目来说，**审批闸门就是唯一那道闸**。所以：

- 会改数据的命令**一律弹卡**，卡面写明执行身份和弹卡理由；
- 纯读命令直放（下一节），但它同样受三道本地护栏约束。

### 2.1 只读白名单：哪些命令不弹卡

**判据只有一条：这条命令会不会改数据？** 三个来源**同时**成立才直放：

| 来源 | 内容 |
|---|---|
| **官方契约** | `dws schema --all --compact` 里 `effect=read` 且 `confirmation=not_required` |
| **本地护栏** | 含命令替换 `$()` / 反引号（**双引号里也算**）、重定向、后台 `&`、环境变量前缀、管道喂给非过滤器 ⇒ 按写处理；`&&` `;` `\|` 逐段判，**每一段**都得过 |
| **人工标注** | 不在「敏感读」清单里（见 2.2） |

**表外一律按写处理，绝不猜。** 所以 `dws api`（原始 OpenAPI）、`dws auth` /
`config` / `profile`、`dws event consume` 这些照旧弹卡 —— 前几个压根不在官方表里，
最后一个是官方标注的 `write`。

官方表共 **1559 条命令，其中 720 条是读**（快照 v1.0.67，2026-11-10）。

### 2.2 敏感读：官方说 `read`，我们仍然弹卡

这几条读出来的东西**本身就是机密**。它们不会被拒绝，但卡面会写明
「会读出密钥」，由用户自己判断要不要允许：

| 命令 | 读出来的是什么 |
|---|---|
| `dev app credentials get` | 客户端凭证（AppSecret） |
| `dev liteapp credential` | 轻应用 OAuth 凭证（含 secret 明文） |
| `devapp +credentials-get` | 开放平台应用凭证 |
| `dev mcp credential get` | MCP 凭证账号详情 |
| `dev mcp credential list` | MCP 凭证账号列表 |
| `dev mcp auth get` | MCP 下游鉴权配置 |
| `aitable supabase api-key list` | SQL Sheet API Key 元数据 |

清单在 `tools/approval_hook.py` 的 `_SENSITIVE_READ`，改一行即可。
**这不是黑名单** —— 点「允许」照常执行，我们只负责把风险摆到卡面上。

### 2.3 卡面上的「策略」一行

弹卡时会写清为什么被拦，四种口径：

| 卡面 | 含义 |
|---|---|
| `写操作（todo +create）· 支持 --dry-run 预演` | 官方标注 `effect=write`；后半句只在官方标了 `dry_run` 时出现 |
| `表外按写（api /v1.0/…）` | 官方表里没有这条命令，按写处理 |
| `会读出密钥：客户端凭证（…）` | 见 2.2 |
| 「含 `$(`（命令替换/重定向）⇒ 按写处理」 | 命中本地护栏 |

卡面说"支持 `--dry-run` 预演"时，可以让 Agent 先带着它跑一遍（那一条本身也不改数据），
看过预演结果再决定要不要发 —— 闸门**不会**替你自动跑：在用户点头之前先执行一次命令，
这件事本身就说不通。

**判据（怎么算这条真生效）**：白名单外的命令**仍然弹卡**；点「拒绝」**真的没执行**；
直放的命令在 `<审批目录>/readonly.log` 里留一行账。

### 2.4 凭据存储：一律拒绝，没有卡可点

CLI 的令牌是**它替用户保管**的东西，Agent 没有任何正当理由去读 ——
所以这一类路径不走"弹卡"，是**直接拒绝**：

| 受保护路径 | 里面是什么 |
|---|---|
| `~/.dws/` | `dws` 的登录令牌（`token.json`）、身份、审计日志 |
| `~/.lark-cli/` | `lark-cli` 的落盘位置（⚠️ 占位：本机还没装，P1-4 接上后按实测修正） |
| `data/wecom-cli-cc/` | 本仓自己的企微 CLI 凭据（`.encryption_key` + `credentials.enc`） |

三条性质，缺一不可：

1. **不弹卡**——拒绝理由是**一句固定文案**，既不带路径也不带命令原文，
   不给模型拼出正确路径的线索；
2. **不看审批开关**——没配 `CC_APPROVAL_DIR` 时也生效（这条规则不需要界面）；
3. **不看免卡白名单**——免卡用户跳过的是"点一下"，不是"这条不能读"。

覆盖面：`Read` / `Edit` / `Write` / `Grep` / `Glob` 按路径字段判（相对路径按本轮
cwd 展开，`..` 与符号链接一并解开），`Bash` 按命令原文判 ——
`~/.dws`、`$HOME/.dws`、`%USERPROFILE%\.dws`、绝对路径、`data/wecom-cli-cc`
这几种写法都算。清单在 `tools/approval_hook.py` 的 `_protected_roots()`。

⚠️ **残余风险（不假装封死）**：运行时**拼出来**的路径（`chr(126)+'/.dws'`）抓不到。
但那条命令本身不在只读白名单里，照样会弹卡 ⇒ 保证的是"**不会一声不响地读**"，
而不是"任何写法都拦得住"。

**判据（怎么算这条真生效）**：`Read` 一个令牌文件 ⇒ 收到拒绝且**没有卡片**；
把 `CC_APPROVAL_DIR` 去掉再试一次 ⇒ **仍然拒绝**；普通文件照旧直放。

所以桥的 `CLAUDE.md` 里单独写了 `dws` 的用法，让 Agent 靠 `--help` / `schema` 自己找。

这不是缺陷 —— 是我们**主动排掉 user 设置**的代价，写在这里免得下一个人当成 bug 去查。

## 4. 执行身份

**用户 OAuth —— 也就是你本人。** 同事收到的消息是你发的，不是你授权的机器人发的。

前置：企业管理员在**开发者平台 → CLI 访问管理**里开启。
✅ 实测走过一次完整流程：`dws auth login` → 浏览器提示"该组织尚未开启 CLI 数据访问权限"
→ 页面提交申请 → 管理员通过 → 命令自动继续并登录成功。

**卡面必须写出这件事。** 本项目在审批卡上加了「身份」一行：

```
身份：钉钉 · 你的账号（不是机器人）
```

判定只看命令的**第一个词**（`dws` / `dws.cmd` / `lark-cli`），
`echo dws` 不算、`cd x && dws …` 算。它**只影响显示，不影响放行**。

## 6. 已知差异

- ⚠️ **`dws dev connect --daemon` 不支持 Windows**（官方文档明写：无 `setsid`、无 POSIX 信号）。
  我们不用那条通道，所以对当前方案无影响。
- **Token 加密存储**：PBKDF2（600,000 次迭代 + SHA-256）+ AES-256-GCM，密钥绑设备；
  Windows 上叠加 DPAPI。**跨设备无法解密** —— 换机器要重新登录。
- **Schema 与 `--help` 冲突时，官方要求按更保守的安全语义处理** —— 这条我们照抄，闸门同理。
- `dws todo +get-my-tasks` 的返回里**没有创建时间**；要核"这条是什么时候建的"得用
  `todo +get --task-id <id>` 取 `createdTime`。

## 7. 实测记录

**读（2026-11-10 14:14:36 → 14:15:51）** —— 企微群，正文「帮我看看钉钉待办里今天有什么？」

| 项 | 数字 |
|---|---|
| 审批卡 / 允许 / 拒绝 | **10 / 10 / 0** |
| 工具调用 / 事件 / 坏行 | 10 / 576 / 0 |
| 退出 | `rc=0 is_error=False 耗时=74.9s denials=0` |
| 独立核对 | `dws todo +get-my-tasks` 返回的待办，`createdTime` 比消息**早 8 秒** ⇒ 是用户先建的，这一轮只**读**到了它 |

⚠️ 10 条工具调用 = 10 张卡，人点了 10 次。这是"全部弹卡"的真实代价 ——
也是命令级白名单（读直放、写弹卡）要解决的第一个问题。

**写（2026-11-10 14:27:08 → 14:27:27）** —— 同一群，让 Agent 建一条带截止时间的待办。

| 项 | 数字 |
|---|---|
| 审批卡 / 允许 / 拒绝 | **2 / 2 / 0** |
| 工具调用 / 事件 | 2 / 66 |
| 退出 | `rc=0 is_error=False 耗时=18.3s denials=0` |
| **钉钉侧创建时间** | **14:27:17** —— 落在「卡①允许（14:27:15）之后、卡②（14:27:20）之前」 |
| **截止时间** | `2026-11-11 16:00` —— 与用户原话「明天下午 4 点」逐字对上 |

**"截止时间对得上"比"任务建出来了"更硬**：它证明模型不只是调通了接口，
而是把那句自然语言正确翻译成了参数。
