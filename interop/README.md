# 生态互联：把官方能力接进来

> **官方能力是插件，我们是插座。**
> 插件由厂商维护、升级、随时换掉；插座只保证四件事：**接得进来、看得见、拦得住、换得掉。**

这个目录回答一件事：**官方已经给 Agent 用的 CLI 和 Skills，怎么接进本项目。**
它不讲"为什么要这么做"（那份在 [联邦式中枢](../docs/federation.md)），
只讲**每个平台差在哪、接的时候会卡在哪一步**。

---

## 一、两条轴，别混

| 层 | 目录 | 回答什么 | 谁维护 |
|---|---|---|---|
| **入口（通道）** | [`platforms/`](../platforms/README.md) | 消息怎么收发、卡片怎么画、`@` 怎么隔离 | **我们**（代码） |
| **执行面** | **本目录** | 官方 CLI 怎么用、以谁的身份、哪些会改数据 | **官方**（代码）+ 我们（闸门） |

一条消息从企微进来，走的是 `platforms/wecom`；Agent 决定去钉钉干活，走的是本目录的
[钉钉页](dingtalk.md)。**两件事不要写在同一页** —— 它们的变化节奏完全不同：
通道层一年不一定动一次，执行面跟着官方一次发布就可能变。

---

## 二、插座模型

```text
          人
   企微    飞书    Slack          ← 入口：人跟 Agent 说话的地方
     \      |      /
      └──────┴──────┘
             ▼
    ┌─────────────────┐
    │  内核（本仓）    │          队列 / 会话 / 审批 / 模型热切换 / 分片
    └────────┬────────┘
             ▼
      Agent（Claude Code）       它自己决定用哪只手
             │
   ┌─────────┼───────────┬────────────────┬─────────────────┐
  本机        P4 设备      钉钉 `dws`       飞书 `lark-cli`
  Bash/文件   MQTT         （官方插件）      （官方插件）
```

**内核不认识"钉钉"或"飞书"。** 新增一个**执行面**，内核不用改；
新增一个**入口**才要写适配器（`platforms/` 契约里的 12 个 `plat_*`）。

四件事分别靠什么保证：

| 职责 | 怎么保证 |
|---|---|
| **接得进来** | Skills 装到 `~/.claude/skills/`；一次安装，所有入口的会话都能用 |
| **看得见** | 审批卡写清「平台 / 目标 / 动作 / 以谁的身份」 |
| **拦得住** | 审批闸门 fail-closed；策略表外的命令按"写"处理 |
| **换得掉** | 执行面是独立进程；坏了、下线了、被厂商改了，拆掉即可 |

## 三、接入六步（对任何官方 CLI 都一样）

| # | 做什么 | 判据（怎么算这步真的成了） |
|---|---|---|
| 1 | **装** | `<cli> --version` 有输出，且来自官方渠道 |
| 2 | **授权** | 官方状态命令回"已授权"——不是"配置文件存在" |
| 3 | **装 Skills** | `~/.claude/skills/` 下出现该平台的 skill 目录 |
| 4 | **让 Agent 认识命令面** | `--help` / `schema` 能列出子命令；**以运行时 schema 为准，不照抄技能文档** |
| 5 | **过闸门** | 真发一条会改数据的命令，确认**弹了卡**；点一次拒绝，确认**真的没执行** |
| 6 | **验一条真实链路** | 一条读 + 一条写，结果都回到入口平台的气泡里 |

⚠️ 第 5 步最容易假通过：**"闸门没跑"和"闸门放行"看起来一模一样**（命令都成功了）。
判据必须是"我看到了一张卡"，不是"命令执行了"。
同族的坑很朴素：闸门命令里一个反斜杠写错，它就连起都起不来，而**外表毫无差别**。

## 四、四个平台，差在哪

| | 官方工作区 CLI | Agent Skills | 执行身份 | 本项目 |
|---|---|---|---|---|
| **企业微信** | `wecom-cli` | 官方技能包 | 授权真人（你本人） | ✅ 已装已授权 · [详情](wecom.md) |
| **钉钉** | `dws` | `dingtalk-*` | 用户 OAuth（你本人） | ✅ 读 + 写已实测 · [详情](dingtalk.md) |
| **飞书** | `lark-cli` | `lark-*` | 用户 OAuth（可 `--as bot`） | ✅ 读已实测 · 写走弹卡 · [详情](feishu.md) |
| **Slack** | 暂无对等 CLI | — | — | 只做入口 · [详情](slack.md) |

**三家共同点**（这一点比差异更重要）：

- 都是**结构化输出 + `--dry-run` + 自带 `SKILL.md`** —— 天生是"给 Agent 用"的，不需要我们再包一层；
- 执行身份都是**你本人**，不是机器人 ⇒ 写操作必须弹卡，卡面必须写明身份；
- 凭据由 CLI 自己加密保管 ⇒ **不进本项目的 `.env`、不进日志、不进公开仓**。

## 五、接一个新执行面，先回答四个问题

1. **它是谁的 CLI？** 官方维护优先 —— 升级和协议漂移不归我们。
2. **它用什么身份执行？** 机器人 / 用户 OAuth / 应用 token。写清楚，别让用户猜。
3. **哪些是读、哪些是写？** 列一张子命令白名单；**表外的按写处理**。
4. **它怎么被 Agent 发现？** 优先 Skills（一次安装，所有入口通用）。

四个都答得出来再动手；答不出来，就先别接。

---

## 六、状态纪律

- 本目录里每条"怎么用"，要么**已实测**，要么明确标 **【待实测】**。
- 没测过的步骤不写"这样就行"，只写"据官方文档，待验"。
- 平台差异只写**事实**（支持什么、前置是什么、有什么限制），不做评价、不排序。
