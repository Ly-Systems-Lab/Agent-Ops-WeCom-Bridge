# 升级与取长补短：吸收新版，而不丢掉你的改动

> **适用**：你已经在本仓基础上改过东西（换 harness、加进度帧、改提示语……），
> 现在上游发了新版，你想**只吸收**对你有用的部分。
>
> **不适用**：你是全新安装 —— 照教程从零走一遍就行，别用本文。

---

## 〇、先记住一句话

**别整份覆盖。** 整份覆盖会把你自己的改动一起冲掉；而本仓的分层恰好让你**不必**整份覆盖 ——
平台层、内核、契约是分开的，多数版本的改动只落在其中一层。

---

## 一、动手之前：留退路

- 文件级备份就够：`cp app/common.py app/common.py.before`（每个要动的大文件一份）；
- 或者开分支：`git switch -c sync/upstream-20261112`；
- ⚠️ 备份要**能被 diff**（单个文件或分支），不要只留压缩包。

---

## 二、第一步永远是哈希树对比

不要直接 `diff -r` 两个仓 —— `.env` / `logs/` / `data/` / `.venv/` 会把重点淹没。
只算代码与文档：

```bash
# 两边各跑一次，得到「sha256 + 相对路径」清单，再比较
python - <<'PY'
import hashlib, os
SKIP = {".git", ".venv", "logs", "data", "__pycache__", ".claude"}
for root, dirs, files in os.walk("."):
    dirs[:] = [d for d in dirs if d not in SKIP]
    for f in files:
        p = os.path.join(root, f)
        if f == ".env" or f.endswith((".pyc", ".log")):
            continue
        print(hashlib.sha256(open(p, "rb").read()).hexdigest(),
              p.replace("\\", "/"))
PY
```

**判据：先看有几个文件真的不同。** 2026-11-12 那次完整的版本跨越，
76 个共有文件里只有 **5 个**不同 —— 工作量就是这 5 个。

---

## 三、对每个不同的文件，先看「删除行」

这是整份流程里**唯一需要判断力**的一步：

| 情况 | 判据 | 做法 |
|---|---|---|
| 纯增量 | 删除行 = 0（`git diff --numstat` 第三列是 0） | **整份替换** |
| 有删除，但删的都不是你的改动 | 逐行看删除行，能对上上游自己的重构 | **整份替换** |
| 删除行里有你的改动 | 出现你加的函数 / 配置 / 分支 | **定点合并**：只挑上游新增的部分，逐处列出 |
| 两边各自演化了同一个函数 | 同名函数两边都在改 | **定点合并**，并把两边的意图写进注释 |
| 测试套件 | 它绑定某一家 harness 的内部接口 | **通常不抄** |

⚠️ **测试套件是最容易抄错的东西。** 本仓的 `tools/test_phase1.py` 直接调 `bridge.Runner`；
换掉运行器之后它**跑不通，但这不代表你的实现坏了** —— 抄进来只会制造"红了但没坏"的噪音。

---

## 四、三项验证 + 回归（重启之前）

1. **语法**：`python -m py_compile app/*.py app/**/*.py`
2. **派生值没变**：打印互斥量名 / 计划任务名 / 关键路径，确认还是你那套（例如 `…-dsh`）
3. **失败路径仍成立**：故意给一个非法值，确认它**拒绝启动**而不是静默放行
4. **回归你独有的能力**：进度帧、熔断、打断、审批 —— 一条一条点一遍

> 「能起来」不算验证。**你的能力还在**才算。

## 六、回滚

> ⚠️ **目前没有发布级回退点。** v1.0.0 之前本仓不打发布 tag ——
> 想留退路请**自己开分支 / fork**，别指望 `checkout v1.0.0`。
> **自 v1.0.0 起**，每个发布点一个 tag，回退就是一条命令。

现在就能用的两种退路：

| 想回到 | 怎么做 |
|---|---|
| 同步之前 | 第一步做的 `*.before` 备份 / 你自己的分支 |
| 上游行为 | 删掉你加的那几个配置键 —— 本仓的设计是「删掉即回上游」 |
