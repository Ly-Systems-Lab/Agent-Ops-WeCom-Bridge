# 外部接入记录

**同一份文档，不同的 Agent，各自从零接入。**

这份目录记录的是**别人**照着本仓教程接入的结果 —— 做对了什么、卡在哪、它自己怎么评价。
内容整理自执行接入的那个 Agent 自己填写的接入记录，我们不代笔改写结论。

---

## 为什么值得记

「这套约定是通用的」是个主张，主张需要证据。

最硬的证据不是我们把文档写得多清楚，而是 —— **几个互不知情的 harness，各自长成了同一个形状**。
教程 [§8 的 6 个适配点](../claude-code-wecom-guide.md) 里，5 个是「同构不同名」：
都有会话句柄、中断接口、审批回调、事件流、终态字段；只有第 1 点（怎么启动一次执行）
的**形态**真不一样 —— 子进程 / HTTP 服务 / JSON-RPC。

这不是我们总结出来的规律，是它们各自撞出来的。

## 适用范围：这是**问题清单**，不是**适配白名单**

上面的 Claude Code / OpenCode / Codex 只是**我们已经验证过的三个样本**，不是支持范围的边界。

任何能跑命令的 Agent 都能照同一套流程接进来 —— 换一家厂商的、开源的、**甚至你自己写的**。
流程完全一样，区别只在教程 [§8](../claude-code-wecom-guide.md) 那 6 个适配点的**答案**：

> **问题是一样的，答案是每个 harness 自己的。**

所以：你的 Agent 不在这张表里，不代表不支持 —— 只代表还没人把答案填一遍。

## 两条被独立验证了两次的结论

单独拎出来，因为它们不是「某个 harness 的怪癖」：

**① `deny` 不是隔离边界。**
OpenCode 那边，`read` 的 deny 规则被 `grep` 绕过去了（grep 的权限资源是正则，不是路径）；
Codex 那边，写权限档位的人自己得出同一句话：「`deny` 不是隔离边界，仍要配 `sandbox`」。

**② 「新会话」不等于「忘掉了」。**
两个 harness 都出现过：`/new` 之后会话确实换了新的，但模型能从磁盘上把旧内容捞回来。

⇒ 所以对外描述 `/new`，请写「**不继承当前上下文**」，不要写「**忘掉了**」。
详见教程 [§6.11](../claude-code-wecom-guide.md)。
