# 外部接入记录

**同一份文档，不同的 Agent，各自从零接入。**

这份目录记录的是**别人**照着本仓教程接入的结果 —— 做对了什么、卡在哪、它自己怎么评价。
内容整理自执行接入的那个 Agent 自己填写的接入记录，我们不代笔改写结论。

---

## 为什么值得记

「这套约定是通用的」是个主张，主张需要证据。

最硬的证据不是我们把文档写得多清楚，而是 —— **几个互不知情的 harness，各自长成了同一个形状**。
教程 [§8 的 6 个适配点](../claude-code-wecom-guide.md) 里，4 个是「同构不同名」：
都有会话句柄、中断接口、事件流、终态字段；第 1 点（怎么启动一次执行）的**形态**
真不一样 —— 子进程 / HTTP 服务 / JSON-RPC；**第 5 点（审批）语义同构、管路不同** ——
`PreToolUse` 子进程 + 目录协议，和进程内回调之间没有现成的桥，换 harness 时通常要重写一层。

这不是我们总结出来的规律，是它们各自撞出来的。

## 回灌：他们改完之后又回来了

上面三份记的是「接进来」—— 作者是别人，结论也是别人写的。
DSH 在接入完成后**又做了一件事**：把上游的新版收回去，同时保留自己那半边。
这提供了另一种证据：**不是一个方向，而是一个闭环**。

一轮完整的往返，一步不少：

| 步 | 谁 | 发生了什么 |
|---|---|---|
| 1 | DSH | 接入后指出单机多桥的两个**系统级名字**没有隔离：互斥量会被第二套桥撞上，装自启会把第一套的计划任务**静默覆盖** |
| 2 | 本仓 | 做成 `BRIDGE_INSTANCE`，并**比提议多守三处**（名字派生同一真源 / 非法值拒绝启动 / 任务名不加平台后缀），发布 |
| 3 | DSH | 新版到了之后，它的 Agent 先做**哈希树对比**：76 个共有文件里只有 5 个不同；`common.py` 是 **+55/−0** 纯增量 ⇒ 整份替换；`host.py` 的删除行里没有一行属于自己 ⇒ 也整份替换；`bridge.py` 定点合并 4 处。**自己的六个适配点、进度帧、熔断、原生打断一处未丢** |
| 4 | DSH → 本仓 | 同一次还回灌了两条**上游缺陷**：图片提示写死了 `Read`（换 harness 就白试一轮）、README 把「会看图」写成了无条件。两条都已按「能力口径」改掉 |

第 3 步的结论是他们自己写的：

> 平台层（6 个文件 ~49 KB）、内核（~81 KB）、契约（2.6 KB）**一行未改**。换的是「大脑」，身体没动。

⚠️ **这句话能成立，是因为边界是做出来的**。`platforms/` 契约 + `tools/check_layers.py`
把「哪些文件属于大脑、哪些属于身体」变成了可机械判定的东西 —— 没有这条缝，
「取长补短」就是一场合并。

⚠️ **诚实口径**：回灌目前是**一例**，而且是 **Agent 干活 + 人在高风险处把关**
（整份替换 / 定点合并 / 决定不抄上游哪一部分）。可以写「照着文档做，Agent 能完成」，
不要写成「全自动同步」。

## 适用范围：这是**问题清单**，不是**适配白名单**

上面的 Claude Code / OpenCode / Codex / DSH 只是**我们已经验证过的四个样本**，不是支持范围的边界。

任何能跑命令的 Agent 都能照同一套流程接进来 —— 换一家厂商的、开源的、**甚至你自己写的**。
流程完全一样，区别只在教程 [§8](../claude-code-wecom-guide.md) 那 6 个适配点的**答案**：

> **问题是一样的，答案是每个 harness 自己的。**

所以：你的 Agent 不在这张表里，不代表不支持 —— 只代表还没人把答案填一遍。

## 两条被独立验证了两次的结论

单独拎出来，因为它们不是「某个 harness 的怪癖」：

**① `deny` 不是隔离边界。**
OpenCode 那边，`read` 的 deny 规则被 `grep` 绕过去了（grep 的权限资源是正则，不是路径）；
Codex 那边，写权限档位的人自己得出同一句话：「`deny` 不是隔离边界，仍要配 `sandbox`」。

**② 「新会话」不等于「忘掉了」。**
两个 harness 都出现过：`/new` 之后会话确实换了新的，但模型能从磁盘上把旧内容捞回来。

⇒ 所以对外描述 `/new`，请写「**不继承当前上下文**」，不要写「**忘掉了**」。
详见教程 [§6.11](../claude-code-wecom-guide.md)。

**③ 回显类字段最容易被「自造」。（新观察，来自 DSH）**
上下文占用这类 footer，文档里有明确契约，但 Agent 第一次写时往往会按自己的命名习惯拼一个
（DSH 写成了 `↑382 ↓726`，既不是占用率也不是比例）。这不是桥的 bug，是**没有逐字对齐契约**。
⇒ 教程 [§6.7](../claude-code-wecom-guide.md) 已写明：这一行是逐字契约，换 harness 时不要自己发明格式；
分母还要有跨进程重启的兜底。
